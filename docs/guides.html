Parcours par situation

Quelles options utiliser, dans quel ordre, selon ce que vous avez devant vous.

Une Fedora fraîchement installée

Le parcours le plus courant. Commencez par regarder ce qui va se passer, sans rien modifier ni saisir de mot de passe : 

$ git clone https://github.com/William-De71/Fedora-Setup.git
$ cd Fedora-Setup
$ ./fedora-setup.sh --dry-run

Adaptez ensuite les listes à vos besoins — voir personnaliser les listes — puis lancez le flux complet : 

$ sudo ./fedora-setup.sh

Le script pose des questions pour les dépôts tiers. Répondez au fur et à mesure, ou utilisez --yes pour tout accepter sans interruption.

Puis, selon la machine

$ sudo fedora-setup --memory     # réactivité (toutes machines)
$ sudo fedora-setup --laptop     # si portable
$ sudo fedora-setup --boot       # si le démarrage traîne
$ sudo fedora-setup --security   # vérification des protections
Carte NVIDIA

Le module noyau est compilé en arrière-plan par akmods : attendez environ cinq minutes avant de redémarrer après la première installation. Vérifiez avec modinfo -F version nvidia. Si Secure Boot est actif, le module doit être signé — procédure RPM Fusion.

Entretien régulier

Le script est idempotent : le relancer ne refait que le nécessaire. Une passe de mise à jour sans toucher au reste : 

$ sudo fedora-setup --no-gpu --no-lists --no-repos

Et de temps en temps, pour récupérer de l'espace :

$ sudo fedora-setup --clean

Sur une machine utilisée quotidiennement depuis quelques mois, il n'est pas rare que --clean libère plusieurs gigaoctets : le cache DNF approche souvent le gigaoctet et le journal systemd peut occuper jusqu'à 10 % de /var avant d'être plafonné.

Avant une mise à jour importante

Sur racine Btrfs, prenez un filet de sécurité : sudo fedora-setup --snapshot. L'instantané est quasi instantané et n'occupe initialement aucun espace.

Portable

Trois options se complètent sur une machine sur batterie :

$ sudo fedora-setup --laptop   # gestionnaire d'énergie, thermald, powertop
$ sudo fedora-setup --memory   # réactivité sous charge
$ sudo fedora-setup --boot     # démarrage plus rapide

--laptop vous fait choisir entre TLP et power-profiles-daemon. Si vous tenez au sélecteur de profil dans le menu système de GNOME, gardez power-profiles-daemon. Si vous voulez le maximum d'autonomie et acceptez de configurer, choisissez TLP.

Pour mesurer ensuite :

$ sudo powertop        # consommation par composant
$ sudo tlp-stat -s     # état de TLP, si installé
$ systemd-analyze      # temps de démarrage

Poste de développement

$ sudo fedora-setup --devtools   # distrobox, KVM, polices
$ sudo fedora-setup --docker     # Docker CE officiel
$ sudo fedora-setup --bashrc     # prompt et PATH personnalisés

--devtools propose chaque outil séparément : vous pouvez ne prendre que les polices, ou seulement la virtualisation.

distrobox ou toolbox ?

Fedora fournit déjà toolbox, qui crée des conteneurs de développement à partir d'images Fedora uniquement. distrobox fait la même chose avec n'importe quelle distribution — utile pour reproduire un environnement Ubuntu ou Debian de production. Les deux cohabitent sans conflit.

Créer un conteneur jetable après installation :

$ distrobox create --name dev --image fedora:latest
$ distrobox enter dev
Groupes docker et libvirt

Ces deux options ajoutent votre compte à un groupe système. Le changement ne prend effet qu'après une déconnexion et reconnexion de la session — pas seulement la fermeture du terminal.

Personnaliser les listes

Le dépôt ne versionne que des gabarits *.list.example. Les fichiers réels sont créés une fois à partir d'eux, puis vous appartiennent : --update ne les modifie jamais.

Paquets RPM et Flatpak

# rpm.list
add:htop
add:neovim
del:libreoffice-core     # retire ce qui ne sert pas

# flatpak.list — identifiant complet
add:org.gnome.Boxes
add:com.spotify.Client

Trouvez l'identifiant d'un Flatpak sur flathub.org ou avec flatpak search <nom>.

Dépôts tiers

Certaines applications — Vivaldi, VS Code, Sublime Text — ne sont pas dans les dépôts Fedora. Une ligne par dépôt, trois champs séparés par | : 

nom | url_de_la_cle_gpg | url_du_fichier.repo

Par exemple :

vivaldi | https://repo.vivaldi.com/archive/linux_signing_key.pub | https://repo.vivaldi.com/archive/vivaldi-fedora.repo

Le script demande pour chaque dépôt s'il faut l'ajouter. Une fois accepté, installez ses paquets comme les autres via rpm.list — par exemple add:vivaldi-stable. Ces lignes sont déjà présentes, commentées, dans le gabarit.

Pour retrouver l'URL et la clé d'un dépôt déjà présent sur votre machine :

$ grep -E 'baseurl|gpgkey|^\[' /etc/yum.repos.d/*.repo

Extensions GNOME

Une entrée par ligne, avec l'UUID de l'extension — visible dans l'URL de sa page sur extensions.gnome.org : 

add:dash-to-panel@jderose9.github.com
del:background-logo@fedorahosted.org
Pourquoi lancer via sudo et non en root

Les extensions GNOME sont un concept par utilisateur : elles vivent dans ~/.local/share et dans les réglages de session. Le script détecte l'utilisateur réel derrière le sudo et exécute les commandes en son nom. Lancé en root direct, cette variable n'existe pas et l'étape est ignorée.

Plusieurs machines

Les options -r, -f, -d et -e acceptent des chemins arbitraires : gardez une liste par machine dans le même dépôt. 

$ sudo ./fedora-setup.sh -r listes/thinkpad.rpm.list \
                          -f listes/thinkpad.flatpak.list

Pour une installation non surveillée, combinez --yes et --quiet : aucune question, affichage compact, détails dans le journal. 

$ sudo ./fedora-setup.sh --yes --quiet

Le script renvoie un code de sortie non nul si au moins une action a échoué, ce qui permet de l'enchaîner dans un script d'automatisation.
