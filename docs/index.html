Fedora Workstation

Post-installation et maintenance, sans refaire les mêmes gestes

Un script unique qui configure une Fedora fraîchement installée, puis l'entretient dans la durée : dépôts, pilotes graphiques détectés automatiquement, paquets, nettoyage, autonomie et sécurité.

Bash Licence MIT Fedora 40+
Sans risque à l'essai

L'option --dry-run affiche exactement ce que le script ferait, sans rien modifier — et fonctionne sans sudo, pour que vous puissiez l'auditer avant de lui confier les droits root.

Ce que fait le script

Lancé sans option, fedora-setup déroule un flux complet de post-installation. Chaque étape est idempotente : relancer le script ne refait que ce qui est nécessaire.

ÉtapeDétail
Configuration DNF Téléchargements parallèles, miroir le plus rapide, 2 noyaux conservés. N'écrase jamais une valeur déjà présente.
Dépôts RPM Fusion free et nonfree (+ tainted), openh264 Cisco, Flathub. Dépôts tiers optionnels via repos.list.
Mises à jour Paquets RPM, Flatpaks et firmwares (fwupd).
Pilotes graphiques Détection par lspci, cumulable sur les GPU hybrides : NVIDIA (akmod, CUDA, VAAPI), Intel (intel-media-driver), AMD (Mesa freeworld).
Codecs ffmpeg complet en remplacement de ffmpeg-free, groupes multimédia RPM Fusion.
Paquets Installation et suppression de RPM et de Flatpaks depuis vos propres listes.
Extensions GNOME Installées par UUID via gnome-extensions-cli, pour l'utilisateur réel derrière le sudo.

À côté de ce flux, huit options autonomes ne s'exécutent jamais d'elles-mêmes : elles font leur travail puis s'arrêtent.

--clean

Nettoyage

Cache DNF, journal systemd, vieux noyaux, TRIM. Affiche l'espace récupéré.

 --memory

Réactivité mémoire

Adapte les réglages du noyau au swap zram de Fedora.

 --boot

Démarrage

Mesure le temps de boot et propose d'en retirer le superflu.

 --laptop

Autonomie

TLP ou power-profiles-daemon, thermald, powertop.

 --security

Sécurité

SELinux, pare-feu, mises à jour automatiques, DNS chiffré.

 --devtools

Développement

distrobox, virtualisation KVM, polices libres.

 --docker

Docker CE

Dépôt officiel Docker, avec buildx et compose v2.

 --bashrc

Bashrc

Installe un ~/.bashrc personnalisé, en sauvegardant l'ancien.

Démarrage rapide

Récupérez le dépôt, puis regardez ce que le script ferait avant de le lancer :

$ git clone https://github.com/William-De71/Fedora-Setup.git
$ cd Fedora-Setup

# Simulation — ne modifie rien, ne demande pas sudo
$ ./fedora-setup.sh --dry-run

# Exécution réelle
$ sudo ./fedora-setup.sh

La simulation affiche chaque commande précédée de $, puis un récapitulatif : 

    Suppression des paquets orphelins : simulé
        $ dnf autoremove -y

==> Récapitulatif
    Mode simulation : 7 commande(s) affichée(s), aucune exécutée.
Avant une grosse mise à jour

Sur une racine Btrfs — le cas par défaut sur Fedora Workstation — --snapshot prend un instantané de / avant toute modification. L'opération est quasi instantanée et n'occupe initialement aucun espace.

Installation en tant que commande système

Pour appeler fedora-setup depuis n'importe quel dossier au lieu de ./fedora-setup.sh : 

$ sudo ./fedora-setup.sh --install

Le script est copié dans /opt/fedora-setup et lié dans le PATH. Ensuite, depuis n'importe où :

$ sudo fedora-setup            # exécution complète
$ fedora-setup --help          # aide
$ sudo fedora-setup --update   # dernière version publiée

Si le dépôt source a un remote origin, --install clone plutôt que copier, ce qui rend --update disponible. Cette dernière suit toujours la dernière release taggée, jamais un commit intermédiaire.

À savoir

--install régénère toujours vos listes de paquets depuis les gabarits : c'est une remise à zéro volontaire. --update, lui, n'y touche jamais.

Listes de paquets

Le dépôt ne versionne que des gabarits *.list.example. Les fichiers réels sont créés une fois à partir d'eux, puis vous appartiennent : aucune mise à jour ne les modifie.

FichierContenu
rpm.listPaquets RPM à installer ou supprimer
flatpak.listApplications Flatpak (identifiant complet)
repos.listDépôts tiers : nom | clé GPG | URL du .repo
gnome-extensions.listExtensions GNOME Shell, par UUID

Une entrée par ligne, syntaxe commune à rpm.list et flatpak.list :

add:paquet     # installe
del:paquet     # supprime
paquet         # équivalent à add:
# commentaire — ignoré, lignes vides ignorées

Voir le guide des listes pour les dépôts tiers et les extensions GNOME.

Principes de conception

Ces règles expliquent pourquoi le script se comporte comme il le fait, et pourquoi il peut être lancé sans le surveiller.

Constater avant de modifier

Une option n'agit que si le contexte s'y prête. cups n'est proposé à la désactivation que si aucune imprimante n'est configurée ; le DNS chiffré est ignoré si votre résolveur est local ; TLP et power-profiles-daemon ne sont jamais installés ensemble.

Réversible par défaut

Les services sont désactivés, jamais masqués. Les fichiers de configuration modifiés sont sauvegardés en .bak. Chaque option affiche la commande qui annule son effet.

Rien d'implicite

Les huit options autonomes ne s'exécutent que si on les nomme. Un sudo fedora-setup classique n'installe jamais Docker, ne touche pas à votre .bashrc et ne désactive aucun service.

Traçable

Chaque exécution écrit un journal horodaté dans /var/log/fedora-setup_*.log, et se termine par un récapitulatif listant nommément les actions en échec.
