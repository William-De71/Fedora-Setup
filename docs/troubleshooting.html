Dépannage

Quand quelque chose ne se passe pas comme prévu

Retrouver ce qui a échoué, annuler un réglage, comprendre ce que le script vous dit.

Lire le journal

Chaque exécution écrit un journal horodaté. C'est le premier endroit où regarder. 

$ ls -t /var/log/fedora-setup_*.log | head -1   # le plus récent
$ tail -f /var/log/fedora-setup_*.log           # suivre en direct

À la fin de chaque exécution, un récapitulatif liste nommément les actions en échec — inutile de remonter des centaines de lignes de sortie DNF : 

==> Récapitulatif
    Réussites : 12
    Échecs    : 1
      ✗ Installation RPM paquet-inexistant
    Détail complet : /var/log/fedora-setup_20260726-101500.log
En simulation

Lancé sans sudo avec --dry-run, le journal est écrit dans /tmp au lieu de /var/log, ce dernier n'étant accessible qu'à root.

Annuler un réglage

Chaque option est réversible. Le script affiche la commande d'annulation au moment où il applique le changement ; les voici rassemblées.

RéglagePour l'annuler
Réglages mémoire (--memory) sudo rm /etc/sysctl.d/99-fedora-setup-memory.conf puis redémarrer
Plafond du journal (--clean) sudo rm /etc/systemd/journald.conf.d/99-fedora-setup.conf
Service désactivé (--boot) sudo systemctl enable <service>
Délai GRUB (--boot) sudo cp /etc/default/grub.bak /etc/default/grub puis sudo grub2-mkconfig -o /boot/grub2/grub.cfg
powertop au démarrage (--laptop) sudo systemctl disable --now powertop-autotune
TLP au profit de PPD (--laptop) sudo systemctl unmask power-profiles-daemon puis désactiver TLP
DNS chiffré (--security) sudo rm /etc/systemd/resolved.conf.d/99-fedora-setup-dot.conf puis sudo systemctl restart systemd-resolved
Groupe docker (--docker) sudo gpasswd -d $USER docker
Ancien .bashrc (--bashrc) cp ~/.bashrc.bak ~/.bashrc
Instantané Btrfs (--snapshot) sudo btrfs subvolume delete /.snapshots/root_...

Messages courants

Cette opération nécessite les droits root

Les options qui modifient le système exigent sudo. Pour les examiner sans privilèges, ajoutez --dry-run : 

$ ./fedora-setup.sh --clean --dry-run

Pas de connexion réseau

Le script vérifie qu'il peut joindre fedoraproject.org avant de commencer, puisque presque tout passe par le réseau. Si votre réseau bloque les requêtes ping alors que la connexion fonctionne, c'est un faux positif — vérifiez avec curl -I https://fedoraproject.org.

Installation non-git : impossible de mettre à jour

--update exige que l'installation ait été faite depuis un clone avec un remote origin. Sans cela, --install se contente de copier les fichiers. Relancez --install depuis un clone à jour.

Aucune batterie détectée

--laptop vise l'autonomie et peut brider les performances. Sur un poste fixe, le script demande confirmation avant de continuer — répondez n si l'option a été lancée par erreur.

Ce résolveur est local — étape ignorée

Ce n'est pas une erreur. Votre DNS est une adresse privée, donc un résolveur de box ou d'entreprise qui répond pour des noms internes. Le remplacer par un résolveur public casserait l'accès à ces ressources : le script s'abstient délibérément.

Étape ignorée : utilisateur cible inconnu

Les extensions GNOME, --bashrc et les ajouts de groupe s'appliquent à l'utilisateur réel, identifié via la variable que sudo renseigne. Lancé en root direct — après un su - par exemple — cette variable n'existe pas. Lancez le script avec sudo depuis votre session.

NVIDIA

Ne redémarrez pas tout de suite

Le module noyau est compilé en arrière-plan par akmods, ce qui prend environ cinq minutes. Redémarrer avant la fin donne un démarrage sans accélération graphique.

Vérifier que le module est prêt :

$ modinfo -F version nvidia

Si la commande ne renvoie rien, la compilation est en cours ou a échoué. Consultez alors /var/log/akmods/.

Secure Boot

Si Secure Boot est actif, un module non signé est refusé au démarrage. Le script le signale lors de l'installation. La procédure de signature est décrite par RPM Fusion. 

$ mokutil --sb-state   # état de Secure Boot

Codes de sortie

CodeSignification
0Terminé sans échec
1Au moins une action a échoué, ou vérification préalable non satisfaite (droits, distribution, réseau)
130Interrompu au clavier. Le récapitulatif est affiché avant de quitter, pour savoir ce qui a déjà été fait

Ces codes rendent le script utilisable dans une automatisation : un sudo fedora-setup --yes --quiet qui renvoie autre chose que 0 signale qu'il faut regarder le journal.
